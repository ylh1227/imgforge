```mermaid
  Offline --> Role
  Role --> Cap[③ 按场景采集至进度满]
  Cap --> Pick{④ 上传通道}
  Pick -->|A| A[网口直传]
  Pick -->|B1| B1[USB 共享网直传]
  Pick -->|B2| B2[PC 暂存再传]
  A --> Check[⑤ 齐套检查]
  B1 --> Check
  B2 --> Check
  Check --> Uploaded[上传完成]
  Uploaded --> Review[⑥ 批量对比图 / 视频]

  BgMatch -.-> Dev
  Dev --> End([归档结束])
```

## 图 2 · ① 任务加载方式（在线 vs 离线）

任务加载有 **两种入口**，最终都是：机端出现同一套任务卡 + 场景清单。  
**区别只在「任务包从哪来」**，不是采集/上传流程不同。

### 一眼对照

```mermaid
flowchart TB
  subgraph ONLINE["在线加载"]
    direction TB
    O1[手机连网] --> O2[登录] --> O3[在线加载] --> O4[刷新列表]
    O4 --> O5[选任务] --> O6[下发场景] --> O7[任务卡就绪]
  end
  subgraph OFFLINE["离线加载"]
    direction TB
    F1[浏览器] --> F2[下 zip] --> F3[拷到手机] --> F4[离线加载]
    F4 --> F5[选本地包] --> F6[解压加载] --> F7[任务卡就绪]
  end
  O7 --> SAME([之后相同：②标定 → ③采集 → …])
  F7 --> SAME
```

| 对比项 | 在线加载 | 离线加载 |
|--------|----------|----------|
| 要不要现场上网 | **要**（连网 + 登录） | **不要**（加载时可不连业务网） |
| 任务从哪来 | 账号登录后 **刷新列表**，点选任务 | **浏览器先下 zip**，手机本地选包 |
| 关键操作 | 刷新 → 选任务 → 加载/重新加载 | 选压缩包 → **解压** → 加载 |
| 场景怎么进手机 | 选任务后从服务器拉取场景 | 从 zip 解压出场景 |
| 典型场景 | 实验室有网、任务常改 | 外场无网/弱网、任务已预发 |

```mermaid
flowchart TD
  Start([打开机端 App · 准备加载任务]) --> Q{现场能否稳定联网登录?}
  Q -->|是| Online([走在线加载 · 图 2a])
  Q -->|否 / 手里已有任务 zip| Offline([走离线加载 · 图 2b])
```

## 图 2b · 离线加载（逐步）

> 路径：**浏览器下 zip → 拷到手机 → 选包 → 解压 → 加载场景**  
> （与在线加载的关键差异：不登录刷新列表，而是 **本地解压压缩包**）

```mermaid
flowchart TD

  C --> D[机端选择「离线加载」]
  D --> E[选择本地任务压缩包]
  E --> F[解压]
  F --> G{解压成功?}
  G -->|否| H[换包 / 重新下载后重试]
  H --> E
  G -->|是| I[从压缩包加载场景]
  I --> K{任务卡出现且机型_SN 可见?}
  K -->|否| D
  K -->|是| L([进入 ② 标定角色])
```

## 图 5 · ④ 上传通道决策

```mermaid
flowchart TD
  Start([采集完成 · 准备上传]) --> Q1{拓展坞网口能通服务器?}
  Q1 -->|是| A([走通道 A])
  Q1 -->|否| Q2{USB 连电脑且能共享网络?}
  Q2 -->|否| Fix[排查线材 / 驱动 / 网络后重试]
  Fix --> Q1
  Q2 -->|是| Q3{需 PC 整理或弱网重传?}
  Q3 -->|否| B1([走通道 B1])
  Q3 -->|是| B2([走通道 B2])
```

| 通道 | 链路 | 落点 | 谁点上传 |
|------|------|------|----------|
| A | 手机 → 拓展坞以太网 → 服务器 | 直达服务器 | 机端 App |
| B1 | 手机 ↔ USB ↔ PC 共享网 → 服务器 | 不落 PC 盘 | 机端 App |
| B2 | 手机 → ADB/panda → PC → 服务器 | 先落 PC 再传 | PC 工具 |

## 图 11 · ⑥ 电脑评审端：批量对比 → 建缺陷

> 齐套后进入 **电脑评审端**：可批量对比图片、视频；对有问题的场景建缺陷，缺陷自动带入对应图片/视频。

```mermaid
flowchart TD
  A([打开电脑评审端]) --> B[选择专项 / 批次]
  B --> C[批量对比图片和/或视频]
  C --> D{当前场景有问题?}
  D -->|否| E[通过 / 跳过]
  D -->|是| F[建立缺陷]
  F --> G[自动带入对应问题素材]
  G --> H[可继续建下一条]
  E --> I{还有场景要看?}
  H --> I
  I -->|是| C
  I -->|否| J{本轮缺陷已建够?}
  J -->|否| C
  J -->|是| K([进入 ⑥c / ⑦])
```

要点：

- 支持 **图片批量对比**、**视频批量对比**（可同一会话内穿插）。
- 建缺陷时系统 **自动挂载** 当前问题素材（图或视频），无需手工再贴附件。
- 可先建一部分缺陷再提交，也可全部建完再提交。

## 图 11b · ⑥c 服务器后台匹配（数据上传完成后触发）

> **触发时机：** 本批图片 / 视频 / log / dump 等 **数据全部上传完成后**。  
> **执行方式：** 由 **服务器在后台自动跑**，不占用电脑评审端操作；与「建缺陷 / 批量对比」并行，**不阻塞评审**。  
> **作用：** 把问题图与对应 dump、时段 log 等数据关联，供开发点图下载。

```mermaid
flowchart TD
  Done([本批数据上传完成]) --> Trig[服务器自动触发匹配]
  Trig --> Bg[后台队列执行匹配算法]
  Bg --> R1[问题图片 ↔ dump]
  Bg --> R2[问题图片 ↔ 时段 log]
  Bg --> R3[其它关联数据]
  R1 --> Ready{后台匹配完成?}
  R2 --> Ready
  R3 --> Ready
  Ready -->|进行中| Parallel[评审端可同时对比 / 建缺陷]
  Ready -->|完成| OK[缺陷详情可取 log + dump]
  Parallel -.-> Gate{开发下载时匹配完成?}
  Gate -->|否| Wait[等待后台匹配结束]
  Gate -->|是| OK
```

说明：

1. 匹配 **不是** 建缺陷时才触发，而是 **上传完成后服务器后台跑**。  
2. 评审同学可边对比、边建缺陷；开发下载 dump/log 时才必须等匹配就绪。  
3. 若匹配迟迟未完成：查本批是否上传齐套、后台队列是否积压。

## 图 12 · ⑦ 按模块指派开发并批量提交

```mermaid
flowchart TD
  A([部分或全部缺陷已建立]) --> B[按模块筛选缺陷]
  B --> C[为模块选择对应开发]
  C --> D[批量提交至缺陷管理平台]
  D --> E{提交成功?}
  E -->|否| F[修正指派 / 重试提交]
  F --> D
  E -->|是| G[缺陷单进入开发侧]
  G --> H([进入图 13 · 开发取证])
```

| 步骤 | 操作 |
|------|------|
| 选模块 | 按成像模块（如 LivePhoto、人像、夜景等）归类缺陷 |
| 选开发 | 每个模块指定对应开发负责人 |
| 批量提交 | 一次把本批问题缺陷推到缺陷管理平台 |

## 图 13 · 开发取证：点图下载 log + dump

```mermaid
flowchart TD
  A([开发打开缺陷管理平台]) --> B[打开有问题缺陷单]
  B --> C[点击缺陷关联的问题图片]
  C --> D[下载问题时间段 log]
  C --> E[下载图片对应 dump]
  D --> F[本地分析 / 定位]
  E --> F
  F --> G{是否修复完成?}
  G -->|否| F
  G -->|是| H[回写缺陷状态]
```

开发侧关键能力：**点问题图即可拉取「该问题时段的 log」+「该图对应的 dump」**（依赖图 11b 匹配结果）。
